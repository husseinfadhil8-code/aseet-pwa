# Mandob Baghdad AI — private seller and item memory

**Implementation for review only. Not deployed. No Cloudflare resources or provider calls created.**

This module lives on `feature/mandob-baghdad`, independently of Waseet's Supabase application and Social Plus's Worker, D1 and secrets. No existing application source or migration is changed. The memory is a core workflow, not a manual import tool.

## Automatic flow

1. Meta GET challenge verifies the dedicated Verify Token. POST verifies HMAC-SHA256 over original bounded request bytes with the App Secret, checks the configured Page, and ignores echoes. PSIDs are Page-scoped, never matched to Telegram/Supabase accounts.
2. Original webhook event is AES-GCM encrypted in a durable D1 inbox. Duplicate Page/message IDs are ignored. Only durable acceptance produces HTTP 200. `waitUntil` starts extraction after acknowledgment; `scheduled` implements recovery. Before activation an isolated recovery schedule must be configured and verified; waitUntil alone is not a delivery guarantee.
3. A page processing lease serializes events. Bounded rules detect seller/buyer/financial intent, literal object names, labelled IQD prices (Arabic and English digits), labelled area and stated condition. Questions explicitly request missing fields; no known name is invented. Followups update the current draft within 24h, and explicit `reply_to.mid` chooses the matching item. A new explicit sale offer creates a separate item, including a second fridge. Ambiguous conversations remain for human review.
4. Draft items link to encrypted seller PSID, the internal conversation ID and original encrypted messages. This internal ID is **not** a fabricated Graph conversation ID. Status starts unknown. A generic sale post never establishes availability. Explicit seller assertions or an administrator's checked confirmation set dated availability; explicit sold statements stop search matches. An old confirmation is never displayed as current verification.
5. Images stay private. Source URLs are encrypted in D1, then bounded HTTPS downloads from Meta attachment CDN hosts only are encrypted in private R2 when the storage gate is enabled. No redirects, public bucket or public image URL. When R2 is not configured, metadata remains pending; do not claim image bytes are already stored. No publishing endpoint exists and publish consent defaults to false.
6. Buyer requests search saved items, record deduplicated interests and prepare an admin alert with the item, seller reference, current saved status, dated last confirmation and a real inbox URL only if an administrator has supplied one. No guessed conversation link and no unknown name are inserted. Financial agreements force handoff and suppress automatic replies for that conversation until an administrator explicitly resumes it.
7. The durable outbox retries failed delivery with leases, bounded exponential backoff and redacted error codes. Alerts send only to the separately configured administrator channel; private photos and PSIDs are not included in Telegram alerts. After 5 attempts the row remains visible for investigation, never deleted. A remote success followed by an ambiguous network/database failure can still cause a duplicate on retry: exactly-once delivery to Meta/Telegram is not claimed.

## Search and real AI adapter

- **Text:** D1 FTS5 with Arabic normalization, safe quoted terms, Page scoping, sold/withdrawn exclusion and bounded results. Names can be added by the administrator after learning them, and the seller registry opens that person's items. Search indexes contain normalized searchable item text; this index is not application-encrypted. Original messages, PSIDs, image URLs, photo bytes and embeddings are application-encrypted. Database access is backend-only.
- **Semantic:** actual Workers AI adapter for `@cf/baai/bge-m3`; encrypted versioned vectors in D1; cosine candidate ranking. Up to 500 recent indexed candidates per search, with an explicit limited flag. The 0.45 threshold is provisional and needs evaluation with authorized Iraqi real-world data, not an accuracy guarantee. This is a small-catalog implementation; no Vectorize resource is created.
- **Images:** actual `@cf/meta/llama-3.2-11b-vision-instruct` caption adapter → multilingual embedding search. Stored images can be indexed automatically after storage or from the admin button. This is visual-description retrieval, **not** pixel-level matching, face recognition, ownership verification or a guarantee of identifying the exact object. Image availability on a CDN is temporary; failed fetches remain visible.
- **Grounded extraction:** optional `@cf/meta/llama-3.1-8b-instruct` analysis; only literal spans in the incoming text can fill missing title/area/condition. Prices remain rules-derived. Rules detecting financial agreements cannot be overridden by the model. Phone-like sequences and links are redacted before text AI analysis. No model receives PSID as a separate field or has database/write tools.
- AI requires an `AI` binding, `ALLOW_AI=true`, the administrator's AI switch and a positive atomic daily call cap. Model failures preserve the private original and rules workflow. Calls/tokens cost money after applicable included quotas; a daily call cap is not a hard dollar cap. No model was invoked in development; tests use adapters with explicit synthetic outputs. Accept model licenses and review image/text processing privacy and budget before activation.

## Administration and security

Arabic RTL single-page mobile dashboard: items and original descriptions, seller registry, text/semantic/image search, private photo preview, buyer interests, dated availability, saved real inbox links, status/name review, settings and redacted delivery log. No customer account is exposed as an admin.

Every data/media endpoint requires the separate strong `ADMIN_TOKEN` (at least 32 chars; provision a cryptographically random secret). The browser holds it only in memory, never URLs or localStorage; logout/reload clears it. Same-origin writes, CSP without inline script/eval, no framing, no public image API. Before production, put the admin dashboard behind Cloudflare Access with MFA and review session revocation; the local bearer gate is implemented, not an existing Waseet login integration.

All replies, external alerts, AI and photo storage have persistent per-Page switches, plus environment gates. Turning off external alerts preserves interest history for review. Switching off replies suppresses pending replies at delivery time. Automatic replies use the standard 24h window based on the signed event timestamp, not the time our server receives it. They never apply HUMAN_AGENT to AI or send promotions. Settings alone cannot override deployment gates. Human handoff and processing failures are retained for review.

Minimum isolated bindings: `DB`, `ASSETS`; later `PHOTOS`, `AI`. Secrets: `DATA_KEY` (32-byte AES key encoded as hex), `ADMIN_TOKEN`, `META_APP_SECRET`, `META_VERIFY_TOKEN`, `META_PAGE_TOKEN`; optional dedicated admin Telegram `ADMIN_BOT_TOKEN` and allowlisted `ADMIN_CHAT_ID`. Install only through the secret manager. Keep encrypted backups of the database and its encryption key separately; losing the key loses access to the encrypted memory. Key rotation and retention/deletion tooling require further production hardening.

`wrangler.example.jsonc` is deliberately a non-deploying template with placeholders, no production IDs, no cron and every external capability off. Review provisioned isolation, Meta approval/permissions, privacy/retention and recovery before creating an actual config. No Waseet/Social Plus production migrations may be used for this module.

## Tests and limitations

`npm test` runs actual SQL/migration/FTS5 using Node SQLite as a D1-compatible test adapter. It tests extraction, followups, duplicate/concurrent delivery, multiple items, tenant isolation, source encryption, challenge/signature, malformed and oversize input, bounded media/SSRF, administrator protection, availability confirmation, financial handoff, durable retry, external send gates, AI budgets and provider contracts. No real Meta, Telegram, R2 or AI service is called.

`node tests/local-server.mjs` starts a loopback-only Worker harness with synthetic users/items. `python3 tests/browser.py` exercises actual local API and SQL plus the browser at 320/390/430/768 widths, login, search, seller list, interest list, confirmation and persistent switches. It does not impersonate a production user. This is not a physical iPhone, Safari or live Meta integration test.

Before deployment: run the migration against isolated local D1/Wrangler and staging D1, restore a backup, configure recovery and authenticated admin identity, check Meta App Review/Page permissions and Send API version, verify real signed text/image events from authorized testers, measure Iraqi intent/search quality, test stale/out-of-order delivery and provider outages, and review resource cost/retention. Do not enable paid models or customer replies until those gates pass. No automatic publishing, payment, financial agreement or cross-project data import is implemented.
