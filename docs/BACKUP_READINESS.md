# بوابة النسخ والاستعادة — Waseet-Test

آخر فحص: 24 أكتوبر 2026 (بغداد). إعداد البيئة المرصود version 9؛ لا ادعاء بإنشاء آلة جديدة. جميع الطلبات مقيدة بالمعرف beyrctbxojpuvhevfyok. لا اتصالات بالإنتاج.

## النتائج الفعلية

- GET project: HTTP 200، Waseet-Test، ACTIVE_HEALTHY، ref مطابق.
- GET /config/auth: HTTP 200؛ لم تُطبع الإعدادات أو الأسرار.
- GET /database/backups: HTTP 200؛ backups=[]، physical_backup_data={}، pitr_enabled=false، walg_enabled=true.
- POST /database/query مع read_only=true وSELECT 1 فقط: HTTP 403، Missing required permission(s): database_read.

زالت أخطاء الصلاحيات الثلاث المطلوبة سابقاً. walg_enabled لا يثبت وجود نسخة. القائمة الفارغة لا تثبت استحالة وجود نسخة خارجية، لكنها لا تقدم نسخة يمكن اعتمادها أو اختبار استعادتها. لم يُطبق SQL كتابة، أو migration، أو restore، ولم تتغير إعدادات Auth/Backups.

## الصلاحية التالية المحددة

إضافة Database: Read (`database_read`) للرمز الحالي مع إبقاء Project Settings/Auth Config/Backups Read، وفي نطاق Waseet-Test فقط. تستخدمها أداة check للاستعلام عن catalog وتاريخ migrations بصلاحية قراءة. لا تطلب هذه الخطوة Database Write أو service_role أو كلمة مرور المدير. بعد تحديث الربط الآمن، يعيد الوكيل التحقق من الهوية أولاً ثم check. لا يعني نجاح check وجود backup.

## المسار الآمن لإنشاء نسخة واختبارها

1. **جرد للقراءة فقط:** إثبات إصدار PostgreSQL والمخطط الحقيقي والمالكين وACL وRLS والدوال وtriggers وتاريخ migrations وعدّ الصفوف وأحجام Storage وAuth. لا نفترض أن القاعدة لا تزال فارغة من نتيجة قديمة.
2. **اختيار المصدر:** إذا ظهرت نسخة مستضافة مكتملة وقابلة للتنزيل، نفحص نطاقها وتاريخها. حالياً لا توجد نسخة ظاهرة. لا نفعّل خطة مدفوعة أو PITR تلقائياً. البديل نسخة منطقية مباشرة من Waseet-Test عبر Supabase CLI/pg_dump، بربط PostgreSQL آمن مناسب من إعداد البيئة، لا بواسطة مفتاح Management للقراءة وحده. هذه الصلاحيات الحالية لا توفر اتصال PostgreSQL أو تنزيل snapshot تلقائياً.
3. **تجهيز الربط عند الحاجة:** يُحدد دور PostgreSQL المسموح ونطاق القراءة والتشفير بعد الجرد. يُربط اتصال المشروع التجريبي فقط كسر بيئة، ولا يُرسل في المحادثة/GitHub. لا نطلب كلمة مرور مدير أو نوسع الوصول إلى الإنتاج. إن تعذر دور قراءة مناسب لجداول Auth/الملكية، نوضح التغطية الناقصة بدلاً من وصف النسخة بأنها كاملة.
4. **الحفظ:** استخراج schema وبيانات التطبيق والتاريخ وAuth اللازم للاستعادة، والتعامل مع أدوار Supabase المدارة وفق أداة المنصة. حفظ النسخة خارج المستودع والسجلات وCI artifacts العامة، مشفرة في وجهة مستقلة دائمة يملكها المستخدم، مع SHA-256 وحجم وتاريخ وmanifest بالنطاق والأداة والإصدار. /tmp وحده ليس نسخة مستقلة دائمة. قراءة Auth config قد تتضمن بيانات حساسة فلا تدخل تقريراً عاماً.
5. **تغطية ما خارج PostgreSQL:** dump لا يحتوي ملفات Storage الفعلية أو أسرار OAuth/SMTP/Edge أو إعدادات المنصة. يلزم نسخ الملفات المسموحة وصلاحياتها وجرد إعدادات إعادة الإنشاء الآمنة بصورة منفصلة. صلاحية database_read لا تمنح Storage API ولا تنزيل كل الملفات. لا نتجاوز نقص الصلاحيات.
6. **اختبار مستقل:** تشغيل PostgreSQL مطابق في حاوية معزولة بلا اتصال إنتاجي، أو Supabase محلي إذا لزم Auth/Storage الحقيقيان. استعادة إلى قاعدة جديدة فقط، وعدم تعطيل FK لتجاهل أخطاء. مقارنة المخطط والصفوف والمجاميع وروابط الصور وتاريخ migrations، ثم اختبار أدوار المدير/المندوب/المحظور والبيع المتزامن والإشعارات والدردشة. أدوار fixtures المحلية ليست اختبار GoTrue حقيقي.
7. **السادسة:** بعد إثبات النسخة واستعادتها، تطبيق السادسة أولاً على النسخة المستعادة واختبار حفظ الصفوف والصلاحيات. عند نجاح ذلك فقط تُنشأ خطة Waseet-Test جديدة بالبصمات ويُطبق المعلق فقط وفق الموافقة المشروطة السابقة؛ لا baselines ولا reset ولا repair. أي خطأ يتبعه تشخيص لا إعادة عمياء.
8. **الإنتاج:** له نسخة مستقلة وترقية مبنية على مخططه واختبار متصل وخطة رجوع؛ نسخة Waseet-Test لا تحمي بيانات الإنتاج. لا اتصال أو تغيير إنتاجي في هذه المرحلة ولا دمج لمجرد نجاح CI.

هذا مسار تنفيذ، وليس إثباتاً بإنشاء نسخة. لم تُنشأ أو تُستعد نسخة مستضافة في هذه الجولة.
