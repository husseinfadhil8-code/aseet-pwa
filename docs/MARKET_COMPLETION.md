# استكمال PR #50 — مرشح غير منشور

استؤنف من رأس PR50 `71d296b`، ووُفّق مع main `a50afd5` (إصدار iOS13)، بما فيه تحديثات الواجهة وإشعارات المحادثة. لا تطبيق جديد ولا إعادة تنفيذ النسخ السابقة. لا دمج أو نشر قبل بوابات الإصدار.

## المنفذ
- تصفح ضيف مستقل، وتصنيفات وبحث وصفحات؛ فلاتر منطقة وسعر وحالة على الخادم. إنشاء/تعديل/بيع/إخفاء/حذف الإعلانات، خمس صور، عرض contain والسحب والأزرار؛ المفضلة والبلاغات ومحادثات السوق المستقلة محفوظة.
- هوية بصرية خضراء/ذهبية وRTL وشاشات هاتف/لوحي. فصل واجهات الحسابات مع إبقاء مسار موظفي وسيط ولوحتهم ووظائفهم.
- إلغاء محتوى السوق الخاص عند الخروج، وفصل محتوى كل نافذة لمنع ظهور رد طلب قديم في نافذة جديدة؛ حماية استجابة الهوية المتأخرة. تحديث رسائل أحدث100 دورياً أثناء الظهور، بلا إرسال Push جديد أو تعديل نظام Push الرسمي.
- إدارة حسابات السوق وتقييدها وإخفاء إعلاناتها، إدارة الإعلانات والبلاغات، وطلبات ترويج ومدفوعات وإعداد رمز التاجر. الإدارة الأصلية للمندوبين والمبيعات والعمولات محفوظة. إحصائيات السوق والمدفوعات من RPC إداري يشمل كامل القاعدة، مع صفحات مستقلة للمستخدمين والإعلانات والطلبات. إجمالي المقبوضات المؤكدة لا يُقدّم كصافي تسوية بعد الاسترداد.
- ترويج يدوي SuperQi:5000IQD/7days، UUID،6حالات، مراجعة استلام حقيقية ورقم حركة فريد، تأكيد ثم تفعيل منفصلان، سجل تدقيق، قفل وتفرد يمنعان ازدواج الحركة والتفعيل. لا بيانات بطاقة ولا QR شخصي ثابت ولا API مفترض. الدفع معطل افتراضياً.
- حذف الإعلان من السوق يحفظ سجل الدفع والبلاغات بدلاً من حذف حركة مالية أو فشل حذف إعلان مروّج بسبب FK. لا يستطيع البائع إرجاع الإعلان المحذوف.
- إسقاط عام محدود للترويج، ترتيب وشارة خادميان، انتهاء تلقائي بالوقت في الاستعلام دون scheduler. حظر الإعلان المخفي أو المباع أو ذي البلاغ المفتوح.
- حدود خادمية أولية لكل حساب:10 إعلانات/ساعة،20 محادثة جديدة/ساعة،40 رسالة/دقيقة،10 بلاغات/ساعة، مع قفل حساب لمنع التزامن وصلاحيات أعمدة تمنع تزوير وقت الإنشاء. تحتاج معايرة ومراقبة إساءة الاستخدام قبل الإطلاق.
- إصلاح مرجع seller_id في RLS إنشاء المحادثة؛ دالة إدارة محدودة تمنع منح الضيوف SELECT على profiles؛ منع تعديل معرف الإعلان أو تاريخ ترتيبه؛ صلاحيات صور وحسابات ورسائل ومال منفصلة.

## التحقق وحدوده
- مصدر الشيفرة النهائي `b96da5bf`؛ أي متابعة توثيقية لا تغيّر ملفات SQL ذات البصمات المرفقة. نجحت محلياً 22 حالة قاعدة بيانات و62 وحدة و17 سوق Chromium، مع نجاح مجموعات الموظفين السابقة. نتيجة CI للرأس الأحدث موثقة في PR50؛ لا تُفسّر انتظار CI في سجل سابق كنجاح.
- `scripts/market_database_tests.py`: PostgreSQL17 فعلي داخل Docker معزول بلا شبكة أو منافذ أو أسرار مصدر. بيانات اصطناعية **للاختبارات فقط وليست نسخة احتياطية**. يشمل RLS والتزوير والتزامن والدفع والترويج والحظر والتخزين.
- اختبارات السوق وواجهة المندوبين في Chromium محلياً؛ Chromium وWebKit عبر CI للرأس النهائي. لا تُسمَّ محاولة عالقة أو ملغاة نجاحاً. مشكلة تجهيز اختبار البحث المتداخل عولجت بانتظار بدء الطلب فعلياً ومهلة8ثوانٍ.
- صور `docs/review/market-390-synthetic.png` و`market-payment-synthetic.png` تركيب اختبار محلي؛ ليست إعلانات أو رمز تاجر فعلياً.
- فحص Management HTTPS متاح بهوية `supabase_read_only_user` فقط. أول DDL رُفض25006 دون تغيير؛ لا محاولة لتجاوز readonly. تحقق عدم وجود market schema/bucket بعد المحاولة.
- راجعت custom event hook `public.rls_auto_enable`: يفعّل RLS على جداول public الجديدة، ولا شبكة/كتابة صفوف مستخدمين. تعريفات وبنود جميع7hooks مثبتة في `scripts/review/market_test_hooks.json`؛ اختلافها يوقف البروفة. لم يعطل أي مشغّل.
- نجحت البروفة النهائية للمخطط عند مصدر `b96da5bf` عبر [40234674546](https://github.com/husseinfadhil8-code/aseet-pwa/actions/runs/40234674546)، ودليل JSON محفوظ في `docs/review/market-test-rollback.json` مع بصمات الملفات الأربع. `hosted_jwt_behavior_verified=false` صراحة.
- وضع `scope=market` اليدوي في workflow البروفة القديم يقتصر على فرع PR50 وهويةTest، يتحقق من بصمات SQL وhooks، ويجرب المخطط ثمROLLBACK ويقارن catalog. لا ينفذ مقترحlegacy ولا يكتب حسابات أو رسائل أو مبيعات مستضافة.

## ما يمنع النشر الرسمي
1. اكتمال CI للرأس النهائي؛ بروفة Test للمخطط نجحت مع rollback، وما زالت اختبارات JWT فعلية للبائع والمشتري والمندوب والإدارة وتسجيل/تأكيد بريد/Storage علىTest. بروفةDDL ليست إثبات السلوك الحقيقي للحسابات.
2. مراجعة RLS وترحيل تزايدي على المخطط الفعلي للإنتاج: لا تستخدم baselineTest للإنتاج. قراءةTest أثبتت حدود goods/sales وحارس صلاحياتprofiles؛ حدود عضويةstaffchat السابقة تحتاج المقترح المراجع واختباراً منفصلاً، ولم تُطبّق هنا.
3. نسخة PostgreSQL **إنتاج** حقيقية واستعادتها، وبايتاتStorage ذات الصلة. النسخة السابقة المتحققة تخصTest فقط؛ لا اعتماد إنتاج متاح في هذه المهمة، ولا بديل اصطناعي.
4. اعتماد رمز تاجرSuperQi الصحيح عبر إعدادات الإدارة، تحقق إجراء المطابقة والاسترداد والدعم، وتجربة أجهزة iPhone/Android فعلياً. Qi API/تسوية آلية/استرداد آلي غير منفذة لغياب صلاحيات ووثائق البوابة.
5. معايرة حدود الاستخدام ومراقبة السبام ودورة حياة الصور المتروكة وإشعارات محادثات السوق وتقارير تسوية واسترداد مالية. محادثات السوق منفصلة ويعمل تحديثها داخل التطبيق؛ لا ندعي توصيل Push لها.

ملفاتSQL مسودة إنشاء أولي، لا تُشغّل على مخطط سوق موجود دون migration تزايدي مراجع. الأوامر التلقائية لا تطبق أيSQL مستضاف.
