## فحوص ما بعد النشر
HTTPS /login=200، /=303، /api/items و/auth/session دون Cookie صحيحة=401. GET Webhook بتوكن اختبار خاطئ وPOST كلاهما 503 لأن GET نفسه ما زال مغلقاً؛ هذه النتيجة متوقعة قبل حفظ Secret. رفض التوكن الخاطئ بـ403 يُختبر بعد تمكين GET، وليس ادعاء فحص حي مكتمل الآن.

مفتاح المالك مطابق قبل/بعد ولا توجد جلسة غير منتهية حالياً؛ الجلسة المخزنة انتهت طبيعياً وفق expires_at ولم تغير العملية تاريخها. اختبار التوقيع الفعلي بمفتاح المستخدم لا يمكن إجراؤه دون تفاعله في Safari؛ صفحة الدخول متاحة ومنطق Passkey اجتاز الاختبارات. يلزم أن يعيد المستخدم الدخول بمفتاحه على هاتفه عند طلب ذلك، ولا نخلق جلسة باسمه أو نقرأ Cookie هاتفه.

## نقطة التوقف الحالية وخطوات الآيفون
تم إنجاز النشر المغلق؛ نتوقف حتى يقول المستخدم «تم حفظ Secret» دون إرسال قيمته.

1. في تطبيق Passwords/كلمات السر على الآيفون أنشئ سجلاً جديداً مستقلاً، وليس تعديلاً لحساب أو Passkey موجود. سمّه Mandob Meta Webhook، ويمكن استخدام موقع Worker واسم مستخدم META_VERIFY_TOKEN لتمييزه. اضغط حقل كلمة السر واختر الاقتراح القوي واحفظه، ثم انسخ القيمة. هذه القيمة رمز تحقق فقط وليست كلمة مرور تسجيل دخول التطبيق أو حساب Facebook. لا تستخدم مولداً عاماً على الويب.
2. Cloudflare > Worker mandob-baghdad-api > Settings > Runtime variables and secrets > Production > Add variable.
3. Type=Secret، Name=META_VERIFY_TOKEN، Value=القيمة المقترحة من جهازك. احفظ/Deploy إذا طلبت اللوحة. لا تضفها كـText ولا تغير أي بوابة أو DATA_KEY.
4. أخبر المشغّل «تم حفظ Secret» فقط. لا ترسل القيمة أو صورة لحقله؛ يمكن قراءة اسم Secret من metadata دون قيمته.
5. بعد هذا التأكيد، موافقة المستخدم الحالية تسمح بتفعيل ALLOW_META_WEBHOOK_VERIFY=true فقط، وإبقاء POST وكل البوابات الأخرى false. يُفحص GET الخاطئ=403 وPOST=503 واعتماد المدير، ثم يعطى المستخدم تأكيد الجاهزية قبل الذهاب إلى Meta.
