# إصلاح إشعارات وسيط — 29 أكتوبر 2026

## النتيجة الحية

الخدمة المسؤولة عن البوت وMini App معاً هي Worker الحالي `waseet-telegram-bot`، على الرابط الرسمي نفسه. نجح تحقق هوية @WaseetIraqMarketBot، ومطابقة معرّف المدير مع حساب root وصلاحية admin الفعلية وعدم حظره، ومطابقة Webhook، والمحادثة الخاصة. التحديثات المعلقة صفر وقت الفحص.

قبل Telegram خمس رسائل حقيقية إلى حساب المدير:

| الرسالة | النوع | Telegram message_id | النتيجة |
|---|---|---:|---|
| اختبار عام | اختبار توصيل | 88 | sent |
| مستخدم جديد | عينة أول بدء للبوت | 89 | sent |
| إعلان جديد | عينة إشعار فقط، دون نشر إعلان | 90 | sent |
| دعوة مؤهلة | عينة إشعار فقط، دون دعوة وهمية | 91 | sent |
| طلب سحب | عينة إشعار فقط، دون مكافأة أو مطالبة مالية | 92 | sent |

كل العينات موسومة «اختبار آمن — ليس نشاطاً أو استحقاقاً حقيقياً»، وموجهة للمدير وحده. سجلاتها منفصلة بعلامة test ولا تدخل عدادات النشاط الفعلي. قبول Telegram ومعرّف الرسالة دليل إرسال من الخادم، وليس دليلاً على قراءة المستخدم أو ظهور إشعار iOS؛ تأكيد الجهاز مطلوب من المالك.

## السبب الحقيقي

لم يكن العطل العام Bot Token خاطئاً أو معرّف مدير مفقوداً. الفحص قبل التعديل أظهر تطابق root، واشتراك المدير وتفضيلاته التشغيلية مفعّلين، وCron يعمل، و19 رسالة مرسلة في الطابور القديم. لكن النظام القديم كان طابور مشتركين بالإعلانات مع عدد محدود من الأحداث، وليس سجل نشاط إداري شاملاً. لم توجد أحداث لأوّل بدء للبوت أو إنشاء الحساب أو الحجز بالحملة. كما خضعت بعض تنبيهات الإدارة لموافقة اشتراك الإعلانات. بقيت إشعارات المكافآت في مسار منفصل محدود.

كشف اختبار الإنتاج أيضاً 403 عند القراءة المباشرة لجداول مطلوب والدعم الخاص بالمساعد. عولجت مطلوب وعروضها وبلاغاتها باستعمال RPC الإدارة الموجودة بعد التحقق الخادمي من root، دون منح صلاحيات SELECT جديدة. دعم المساعد يكتب بالفعل في جدول الدعم الأساسي ضمن المعاملة نفسها؛ استُخدم هذا السجل الأصلي عوض مراقبة نسخة ثانوية غير متاحة. لا يوجد مصدر مراقبة نشط فاشل وقت التحقق النهائي. يوجد أثر خطأ Webhook قديم مسجل لدى Telegram؛ لا يثبت تعطلاً حالياً مع صفر تحديثات معلقة ونجاح إرسال الاختبارات. أضيف my_chat_member إلى allowed_updates دون إسقاط التحديثات المعلقة.

## مصفوفة الأحداث

| طلب المالك | آلية التقاط الحدث | التحقق |
|---|---|---|
| أول بدء للبوت | trigger D1 عند الانتقال الحقيقي started:0→1 أو الإدراج started=1 | اختبار عدم التكرار + عينة حية 89 |
| أول تسجيل فعلي في Mini App | هوية Telegram موثقة، حساب حقيقي، وعلامة أول تسجيل محفوظة | اختبار زائر/مستخدم قديم/تسجيل جديد |
| إنشاء حساب وطلب مندوب | مراقبة users وrep_applications وربط RPC | تصنيف وانتقالات وصلاحيات آلياً |
| إعلان جديد مع العنوان والسعر والصاحب والصورة إن أمكن | سجل listings، وحل هوية المالك، وجلب الصورة الخاصة خادمياً | آلي + عينة إشعار حية 90؛ لم ننشر إعلان اختبار |
| المراجعة والتعديل والحذف | مقارنة سجل الإعلان بعد الكتابة ومراقبة الخلفية | اختبارات الانتقالات |
| الاعتماد والرفض | تغير approved_at/status؛ يُحفظ مسار المستخدم القديم | اختبارات الانتقالات والتنبيهات القديمة |
| النشر في القناة | publications.state=sent من مسار نشر المنصة | اختبار تصنيف + مراقبة حية سليمة |
| إنشاء مطلوب وتغير حالته | قراءة الإدارة الرسمية وRPC الكتابة | اختبار الإسقاط المصرّح + مراقبة حية سليمة |
| عرض على مطلوب | admin_offers مع ربط الطلب وصاحبه | اختبار التصنيف + مراقبة حية سليمة |
| التسجيل بالحملة | trigger إدراج الحجز في D1 | اختبار آلي، دون حجز تجريبي في الإنتاج |
| دعوة مؤهلة | trigger الانتقال إلى qualified بمفتاح فريد للمدعو | اختبار 30 حالة + عينة حية 91 |
| بلوغ 30 دعوة | عدّ المؤهلين بعد تاريخ الاشتراك وإشارة مرة واحدة | اختبار trigger معزول؛ ليست 30 دعوة بشرية حقيقية |
| طلب السحب | trigger إدراج المطالبة؛ تحويل المسار المالي القديم للمركز | اختبار آلي + عينة إشعار حية 92 |
| اعتماد/رفض/تأكيد دفع السحب | trigger تغير حالة المطالبة | اختبار آلي؛ لا تحويل أو دفعة إنتاجية تجريبية |
| البلاغ والدعم | السجلات الأصلية والتغيرات المصرّح بها | اختبارات التصنيف والمراقبة |
| محادثة تحتاج تدخلاً | بلاغ أو تصعيد دعم صريح، دون قراءة محادثات خاصة عادية | اختبار التصنيف والصلاحيات |
| خطأ مهم | catch خادمي، رمز آمن، ومفتاح منع تكرار لمدة خمس دقائق | اختبارات الطابور + ظهور أخطاء 403 الحقيقية ثم إصلاحها |

لا يوجد نموذج مستقل «عرض سعر على إعلان» في المشروع الحالي؛ التواصل مع بائع الإعلان عبر الرسائل، والعروض المنظمة موجودة ضمن مطلوب. لم نختلق حدثاً أو بيانات لميزة غير موجودة.

## الطوابير والإعدادات

أضيفت جداول وأحداث وtriggers في D1 الموجودة بالترحيل 010، بعد نسخة تشغيلية مشفرة خاصة. لا تغيير لمخطط Supabase أو RLS أو صلاحيات المستخدمين، ولا حذف لحساب أو إعلان أو محادثة. بقي سجل النقود والحجوزات مطابقاً لما قبل الاختبارات، وحملة ادعُ واربح فعالة، والميزانية الخاصة غير مكشوفة.

المدير يستقبل من الخادم إلى المعرّف الذي يتحقق من دوره الفعلي، دون الاعتماد على فتح Mini App أو الاشتراك التسويقي. البوت والتطبيق يكتبان في سجل الإدارة نفسه. تنبيهات المستخدمين القديمة للرسائل والاعتماد والمندوبين والرادار بقيت في طابورها المختبَر، وتضاف الأنواع التشغيلية الناقصة من المركز، مع احترام enabled/operational والإيقاف المؤقت والحظر والموافقة وأنواع المستخدم. بدء البوت لا ينشئ موافقة تسويقية.

مركز الإشعارات متاح للمدير من حسابي، ويضم الأحداث، العدادات، حالات الإرسال، معرّف رسالة Telegram، الرموز الآمنة للأخطاء، الاختبار، إعادة المحاولة الصريحة، وتشغيل كل نوع وإيقافه. روابط الإدارة تحمل رمزاً عشوائياً يفتح الحدث المحدد ثم الإعلان أو الحساب أو الطلب أو السحب المرتبط به بصلاحياته؛ لا ينقل الرابط صلاحية ولا يكشف رقم الهاتف أو الميزانية.

الإرسال محمي بمفتاح حدث فريد، وحجز معالجة، وتباطؤ. 429 يعاد بعد retry_after؛ الأعطال المعروفة والحظر تبقى في الطابور بإعادة محاولة مؤجلة. فشل التحقق قبل الإرسال لا يرسل إلى بديل غير مخوّل. الانقطاع أو timeout بعد الإرسال قد يعني أن Telegram استلم الرسالة دون وصول الرد؛ يحتفظ المركز بها كحالة review ويتيح إعادة محاولة مؤكدة بعد المراجعة. Telegram Bot API لا يقدم مفتاح exactly-once، لذلك لا نعد بضمان عدم التكرار مع إعادة عمياء لنتيجة مجهولة. التنبيه لا يُحذف أو يُعتبر مرسلاً دون message_id مقبول.

لمنع التكرار بين الأنظمة السابقة والمركز، تُحوّل طلبات المندوبين الإدارية وتنبيهات الدعم القديمة إلى المركز، ويُستخدم message_id الحقيقي عند الإقرار في النقل القديم إن توفر. سجل المرشد القديم قد يعرض عملية التحويل برمز delegated_notification_center؛ مرجع نتيجة التسليم هو المركز الجديد.

## حدود التقاط التغييرات

تغييرات D1 المذكورة تكتب الحدث في معاملة البيانات نفسها. أما Supabase فيُلتقط من مسارات RPC مع مراقبة دورية كل دقيقة، لأننا لم نحصل على صلاحية مالك لتثبيت triggers جديدة هناك ولم نوسّع الامتيازات. الحالة النهائية والسجلات الجديدة تُستعاد بالمراقبة إذا تعطل الربط المؤقت. لا نزعم سجلاً معاملاتياً كاملاً لكل تعديل خارجي متعاقب داخل قاعدة Supabase بين دورتين؛ تغييران خارجيان يعيدان الصف إلى قيمته الأولى بين الفحصين قد لا يظهران. التصفح المجهول وكل إعادة فتح ليست تسجيل مستخدم جديد.

إسقاط الإدارة لمطلوب يُقرأ على صفحات محدودة، وعروض الطلب من واجهته الرسمية المحدودة. تجاوز حدود الصفحات يظهر كخطأ مراقبة بدلاً من ادعاء اكتمال الفحص. لا يتضمن هذا العمل اختبار ضغط آلاف المستخدمين.

## الاختبارات والملفات

نجحت 152 حالة JavaScript، وحزمة واجهة Chromium ذات 91 اختباراً، وثلاث حالات إضافية خاصة بمركز الإشعارات وصلاحياته والرابط المعني. نجحت اختبارات D1 الجديدة لكل قوالب التنبيهات والتكرار والصلاحيات و429 والنتيجة المجهولة والتسجيل وtriggers الدعوات والسحب، وكذلك اختبارات حفظ الإعلان مرة واحدة والحملة النقدية. الصور ونقلها كبيانات خاصة مغطاة باختبارات ناقل Telegram القائمة؛ عينات الإنتاج الخمس كانت نصية. لم يُختبر جهاز iPhone فعلي.
