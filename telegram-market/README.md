# وسيط داخل تلغرام — مرشح غير منشور

المشروع الحالي للبوت `@WaseetIraqMarketBot` داخل مستودع وسيط نفسه، عبر PR #56 وفرع `feature/telegram-market-starter`. لا يغيّر التطبيق الأصلي أو سوق PR #50. Worker المستهدف `waseet-telegram-bot`؛ الواجهة والخادم يُنشران معاً من `wrangler.jsonc` على Cloudflare Workers Assets.

## ما نُفّذ
- سوق عربي RTL للهاتف وsafe-area الآيفون، بحث وأقسام وفلاتر سعر وصفحات، صور contain بالسحب، وإعلانات حقيقية مشتركة عند توصيل القاعدة. لا إعلانات وهمية أو localStorage باعتبارها منشورات.
- حساب موثّق بتوقيع Telegram initData الخادمي، صلاحية ساعة ورفض المستقبل والتكرارات والتزوير. لا استخدام initDataUnsafe للتفويض، ولا اعتماد على username لتحديد المدير.
- نشر/تعديل/بيع/حذف، خمس صور مضغوطة JPEG دون قص مع إزالة بيانات الملف الأصلية، مفضلة وبلاغات ومحادثات خاصة بين الطرفين مع تحديث أثناء الظهور.
- لوحة مستخدمين وإعلانات وبلاغات ودعم ومدفوعات، وإدارة صلاحيات وحظر. المندوب يرى مبيعاته وعمولاته فقط، وتسجيل العملية المالية للإدارة برقم فريد. سجلات تلغرام منفصلة عن مبيعات/عمولات وسيط الأصلية؛ لا ربط غير موثق لحسابات الموظفين القديمة.
- صور في bucket خاص؛ لا روابط Storage عامة. الخادم يسمح بعرض الصورة للإعلان النشط أو لصاحبها، ويفحص نوع وحجم الرفع وحده5MB، مع سقف100 صورة للحساب و30 محاولة رفع بالساعة و10 إعلانات بالساعة.

## Stars وقواعد تلغرام
- الترويج خدمة رقمية: Telegram Stars بعملة`XTR` فقط، provider_token فارغ، ولا Qi/QR/بطاقة/دفع خارجي لهذه الخدمة داخل تلغرام.
- `PROMOTION_STARS` غير مضبوط افتراضياً: الدفع معطّل حتى اعتماد السعر. لا تحويل مفترض من5000 دينار إلى Stars.
- إنشاء فاتورة أو callback نافذة الدفع لا يُفعّل الإعلان. pre_checkout يُطابق صاحب الطلب والمبلغ والعملة والحالة، والتفعيل بعد successful_payment الموثّق منWebhook وحده.
- رقم طلب UUID وقيد حركة Telegram فريدة وقفل صفوف يمنعان ازدواج الطلب/الدفع/التفعيل. المدة7 أيام ثابتة. إخفاء الإعلان أو بيعه يمنع عرضه ممولاً؛ إن تغيّرت حالته خلال الدفع تُسجل الحركة للمراجعة ولا يُفعّل.
- دعم`/paysupport` و`/terms` وتذاكر دعم. الإدارة تستطيع رد Stars عبر refundStarPayment؛ فشل/انقطاع نتيجة الرد يُجمّد الطلب للمراجعة، ولا يُعاد الخصم/الرد تلقائياً. المحظور يحتفظ بإمكانية طلب الدعم وقراءة مدفوعاته.
- مراجع رسمية: [Mini Apps](https://core.telegram.org/bots/webapps)، [Stars](https://core.telegram.org/bots/payments-stars). لا اختبار دفع حقيقي أو استرداد مستضاف قبل توفر الاعتماد والبيئة المناسبة.

## Cloudflare والأسرار

الأسرار تُدخل في Dashboard ← Workers & Pages ← waseet-telegram-bot ← Settings ← Variables and Secrets، بالنوع Secret فقط:

- `TELEGRAM_BOT_TOKEN`: رمز هذا البوت تحديداً من BotFather.
- `SUPABASE_SERVICE_ROLE_KEY`: مفتاح legacy service_role لمشروع **Waseet-Test**، لا anon أو كلمة مرورDB. يبقى على الخادم ولا يُرسل للواجهة.
- سرWebhook وسر إعداد مؤقت يولدهما `scripts/configure_cloudflare.py` بعد تفويض Cloudflare؛ لا تطلبهما من المستخدم ولا تطبعهما.

متغيرات غير سرية: `SUPABASE_URL` مضبوط علىTest فقط في إعداد النشر، `ADMIN_TELEGRAM_IDS` قائمة معرفات رقمية يحددها المالك، و`PROMOTION_STARS` سعر يوافق عليه المالك. `keep_vars` يحفظ إعدادات Dashboard غير الموجودة في الملف. لا يحدد أول مستخدم نفسه مديراً، ولا يوجد مدير/سعر مدفوع افتراضي.

تفويض Codex يحتاجCloudflare API Token بصلاحياتWorkers Scripts:Edit وAccount Settings:Read للحساب المستهدف؛ يضاف إلى بيئةCodex للمضيفapi.cloudflare.com، وليسGitHub أو المحادثة. أسرارWorker وحدها لا تمنح صلاحية النشر. الربط التلقائي عبرActions يحتاجسرّي`CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` فيActions، أو ربطGitHub الرسمي منCloudflare بواسطة المالك. لا يُنسخ Network Secret placeholder إلىGitHub.

Workflow`telegram-market.yml` يختبر ثم ينشر تلقائياً من فرع البوت فقط إذا توفر التفويض. إذا غاب يعلن صراحةً عدم النشر؛ نجاح الاختبارات ليس نجاح نشر. لا يُنشر التطبيق الأصلي. لا migrations تلقائية في deploy.

بعد النشر، سكربت الإعداد يتحقق منgetMe واسم البوت وقاعدة البيانات، ويربطWebhook معsecret_token ويحفظpending updates ويضبطالأوامر وزرالقائمة، ثم يتحقق منgetWebhookInfo وHTTPالواجهة وAPI. يحذف مفتاح الإعداد المؤقت فيfinally. `/health` دليل حياةWorker فقط، لا دليل عملالسوق أوتسليمTelegram.

## قاعدة البيانات

`db/001_telegram_market.sql` إنشاء إضافي معزول لـ11 جدولاً بأسماءtg_market_* ودوال محدودة وbucket خاص. جميعهاRLS، ولا صلاحياتanon/authenticated للجداول أوRPC. الهوية والأدوار تأتي منخادمWorker الموثق؛ service_role لا يظهر للعميل. لا تعديل أوحذف لجداولالسلع/المبيعات/المندوبينالقديمة.

- اختباراتPostgreSQL المعزولة: `python telegram-market/tests/database.py`، بلا شبكة/منافذ/أسرار مصدر. بياناتهااصطناعية للاختبارات فقط، ليستنسخةاحتياطية.
- بروفةTest اليدوية: workflowالترحيلالحالي بوضعscope=telegram، وconfirm_test_ref الصحيح، علىفرعالبوت فقط. يتحقق منبصماتSQL وDDLhooks ثمينفذداخلTransaction،يفحصRLS ويعملROLLBACK ويقارنcatalog وbucket. لا حسابات أو رسائل مستضافة.
- البروفة ليست تثبيتاً دائماً للمخطط ولا اختبارStorage/Auth/Telegram فعلياً. لا تطبيق علىإنتاج دون مخطط مراجع ونسخة إنتاج قابلة للاستعادة. نسخةTest السابقة ليستنسخةإنتاج.

## التشغيل المجاني وحدوده

Worker يستجيب عند الطلب؛ لا يحتاج خادماً شغالاً باستمرار. الخطة المجانية محدودة بطلبات/CPU Cloudflare وحصصSupabase/Storage وTelegram، وليست ضمان تشغيل مطلق. لا موارد مدفوعة تُنشأ آلياً. تحديث الرسائل كل5ثوانٍ أثناءالظهور؛ لاpollingخلفي ولاcron أوrealtimeفاتح لكلضيف. تلزم مراقبةالحصص، وتنظيف الصور اليتيمة وتسوية حالاتrefund_review قبلالإطلاق العام.
