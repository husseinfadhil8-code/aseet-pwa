عندما تكون نافذة وسيط مركّزة وظاهرة وفي المجموعة أو الخاص، يسجل التطبيق المحادثة المفتوحة للجهاز الحالي. الخادم يتجنب إرسال Push المطابق فقط؛ تبقى تنبيهات المحادثات الأخرى والأجهزة الأخرى والأحداث غير الدردشة. المغادرة والرجوع للقائمة وفقدان التركيز والخلفية تطلب مسح الحالة.

## الآيفون

لا نخفي Push بعد وصوله ولا نغلقه فور عرضه. [WebKit يشترط عرض إشعار لكل Push يصل](https://webkit.org/blog/12945/meet-web-push/)، وقد يلغي الاشتراك عند مخالفة userVisibleOnly. لذلك بقي handler العامل يعرض كل Push يصل إليه، والمنع يحدث قبل الإرسال في خدمة الإشعارات.

## الحالة والأمان

- `chat_visibility` يستعمل JWT المستخدم، ويطابق actorId لمنع استجابة حساب قديم، ثم يختار اشتراك الجهاز بشرطي user_id وendpoint. المحادثة تتطلب عضوية المستخدم.
- لا جدول أو migration أو سياسة جديدة. تضاف `waseet_chat_visibility` إلى JSON الاشتراك الموجود، مع page_id وconversation_id وexpires_at بتوقيت الخادم؛ تزال هذه metadata قبل تمرير الاشتراك إلى web-push.
- تحديث كل أربع ثوان أثناء القراءة فقط، ومدة الصلاحية 12 ثانية. تكرار الحالة الخالية لا يرسل طلبات دورية. التبويب الخلفي لا يمسح حالة تبويب آخر، والأخطاء لا تلغي الاشتراك ولا تعرض أسراراً.
- انقطاع الاتصال أو توقف التطبيق المفاجئ قد يؤخر زوال الحالة حتى 12 ثانية؛ قد تُحجب رسالة خلال هذه المهلة. الإشعارات المرسلة سابقاً إلى خدمة الجهاز لا يمكن سحبها بهذا التعديل. النظام لا يدعي معرفة حالة الجهاز لحظياً عبر شبكة منقطعة.
